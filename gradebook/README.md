# ПОС - преподавательская оценка студентов

## Запуск

Понадобится Go 1.21 или новее. При первой сборке Go скачает зависимость `go.uber.org/dig`. Из корня проекта выполните:

```sh
go build ./...
go test ./...
go run ./cmd/gradebook
```

В меню пункты **1-4** добавляют и показывают студентов и критерии, **5-8** работают с оценками, **9-11** показывают и экспортируют итоги. Пункт **12** запускает демонстрацию, **0** завершает программу. Оценка, максимум и вес вводятся целыми числами. Для экспорта можно указать путь или нажать Enter, чтобы записать `totals.csv` в текущую папку. Экспорт в существующий файл с тем же именем заменяет его содержимое.

Журнал хранится в памяти в течение одного запуска. CSV сохраняет итоговую ведомость на диске.

## Сквозная демонстрация

На пустом журнале выберите пункт **12**. Для автоматического прогона из терминала:

```sh
printf '12\n0\n' | go run ./cmd/gradebook
```

Демо добавляет трех студентов и три критерия, выставляет оценки, показывает отклонение завышенного балла, оценки по отсутствующему критерию и дубликата, затем выводит итоги и сохраняет `demo-totals.csv`. При политике по умолчанию файл содержит:

```csv
student_id,student_name,total
s1,Иван Петров,81.00
s2,Анна Иванова,66.00
s3,Олег Смирнов,18.00
```

Чтобы проверить изменение итога, после демо исправьте оценку `s1` по `hw` с 8 на 9 через пункт **6**. Пункт **9** покажет 84,00. Затем отмените оценку `s1` по `exam` через пункт **7**. Новый итог будет 54,00.

## Карта DDD

| Термин предметной области | Тип и роль | Правила |
|---|---|---|
| Студент | `Student` - сущность и корень агрегата с идентичностью `StudentID` | Имя и ID обязательны. Студент управляет своими оценками. На один критерий у него приходится максимум одна оценка. Исправление и отмена требуют существующую оценку. |
| Рубрикатор | `Rubric` - корень агрегата, содержащий критерии | ID критериев уникальны в пределах рубрикатора. Сумма весов может быть меньше 100 при заполнении рубрикатора и не может превысить 100. |
| Критерий | `Criterion` - сущность с идентичностью `CriterionID` внутри рубрикатора | Название обязательно, максимум положительный, вес - от 1 до 100. |
| Оценка | `Evaluation` - запись внутри агрегата студента, определяемая критерием | Выставление и исправление сверяют критерий с рубрикатором и проверяют балл в диапазоне от 0 до максимума включительно. |
| Итог | `Total` - объект-значение, результат доменного сервиса `TotalCalculator` | Сервис использует актуальные оценки студента и веса из рубрикатора. Итог вычисляется по запросу. |

`StudentID`, `CriterionID`, `MaxScore`, `Weight` и `Score` - объекты-значения (Value Objects). Например, два значения `CriterionID`, созданные из `"hw"` и `" hw "`, равны после нормализации, а критерий с этим ID сохраняет свою идентичность при переименовании. `Score` создаётся с учётом максимума критерия, который агрегат студента получает из текущего рубрикатора.

`StudentRepository` и `RubricRepository` - выходные порты в домене. Доступ к агрегату рубрикатора и агрегату студента координирует `GradingService`. Проверка допустимости изменения остается в `Student`. `TotalCalculator` вынесен в доменный сервис, поскольку расчет использует данные обоих агрегатов.

## Подсчет итога

Вклад критерия равен `балл / максимум * вес`. Правило по умолчанию (`strict`) складывает эти вклады на шкале 0-100. Пропуск даёт нулевой вклад, а рубрикатор с суммой весов 80 дает максимум 80. У Ивана из демо получается `8/10 * 30 + 9/10 * 30 + 15/20 * 40 = 81`.

Правило `graded-only` делит сумму вкладов на сумму весов критериев с оценками и умножает результат на 100. Выставленный ноль входит в сумму весов. При отсутствии оценок итог равен нулю. Смена правила действует на все итоги текущего запуска:

```sh
go run ./cmd/gradebook -policy graded-only
```

Анна из демо получит 94,29 вместо 66,00, поскольку её оценки покрывают критерии с общим весом 70. Округление до двух знаков выполняется после вычисления суммы или нормализации.

## Архитектура Ports and Adapters

| Пакет | Ответственность |
|---|---|
| `internal/domain` | Сущности, объекты-значения, инварианты, расчет итога, порты репозиториев. |
| `internal/application` | Сценарии через `Gradebook`, команды, модели вывода и порт `TotalsExporter`. |
| `internal/adapters/console` | Входной адаптер. Читает ввод, вызывает сценарии, показывает данные и ошибки. |
| `internal/adapters/memory` | Выходной адаптер. Реализует порты репозиториев и хранит журнал в памяти. |
| `internal/adapters/export` | Выходной адаптер. Реализует порт экспорта и формирует CSV. |
| `cmd/gradebook` | Точка сборки приложения. Выбирает политику, регистрирует конструкторы в DI-контейнере `dig` и запускает консоль. |

Зависимости исходного кода направлены внутрь:

```text
console -> application -> domain
export -> application
memory -> domain
console -> domain
```

На этапе запуска `dig.As` связывает реализации репозиториев и CSV-экспорта с их интерфейсами. Контейнер передаёт один экземпляр каждого репозитория сценариям, которые используют общий журнал. Сценарии получают зависимости через конструкторы.

## Паттерны GoF

| Группа и паттерн | Реализация | Задача |
|---|---|---|
| Порождающий - Builder | `domain.RubricBuilder`, используется в `RubricService.AddCriterion` | Собирает рубрикатор из исходных полей. Создает объекты-значения и делегирует проверку суммы весов агрегату. При расширении собирает новый список критериев и возвращает первую ошибку. Неудачная сборка оставляет исходный список прежним. |
| Структурный - Facade | `application.Gradebook` | Дает консоли единый интерфейс сценариев для студентов, рубрикатора, оценок и отчетов. Консоли не нужно собирать их сервисы и репозитории. |
| Структурный - Decorator | `domain.RoundedPolicy` | Реализует тот же интерфейс `TotalPolicy` и применяет округление к результату выбранного правила. Обе стратегии используют одно представление точности. |
| Поведенческий - Strategy | `domain.TotalPolicy`, `StrictPolicy`, `GradedOnlyPolicy` | Позволяет выбрать трактовку отсутствующих оценок в точке сборки. `TotalCalculator` одинаково собирает данные для обеих политик. |
